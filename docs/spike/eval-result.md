# 0.8B の訳文の評価結果

docs/HUMAN_TASKS.md 8節「訳文を読む」の記録。モデルは `plamo-3-translate-0.8b-Q4_K_M.gguf`、記事は docs/spike/eval-articles.txt の順。訳文のファイルはコミットしない(docs/spike/eval-out/)。

観点と重さ: 否定・数値・訳抜け・コードとURL は重大。固有名詞と専門用語は軽微(意味が変わる固有名詞は重大)。

## 評価の方法

- 人が自分で読むのは難しかったため、人が別の AI に訳文ファイルを渡して評価させ、その結果をエージェントに渡した(2026-11-14)。HUMAN_TASKS の手順(人が読む)とは異なる。
- 別 AI の評価は、目立つ誤りを挙げた定性的なもので、全 988 段落を網羅的に数えたものではない。下の表の数は、別 AI が挙げた箇所の数。
- エージェントが訳文ファイルで一部を確かめ、指摘どおりであることを確認した: 「合気道」(記事4と7で計 12 か所。同じ記事の中で `Aikido` のまま残った箇所もある)、「風上」(記事4)、「侵入者」(記事7、9)、「遺言執行」(記事9)、「1,020歩」(記事10)、「模擬面接」(記事6)、「汚職」(記事8)、「設定の解像度」(記事5)、「持続可能なワークフロー」と「飛行中」(記事10)。記事9 段落65 では、原文でバッククォートに囲まれたパス `//front-door//back-room/` が `//玄関//奥の部屋/` に訳されていた。

## 別 AI が挙げた、翻訳処理側の改善点(Phase 3 の参考)

1. 固有名詞、コードスパン、パス、URL を翻訳させず、訳文に原文と同じ形で残ったかを検証する。
2. 技術用語の訳語を固定する用語集(`durable`、`in-flight`、`backing store`、`transitive dependency`、`reachability` など)。
3. 本文の抽出を改善する(見出しのリンク文字列「Copy link to heading」や、重複した製品名などの UI 由来の文字列を除く)。
